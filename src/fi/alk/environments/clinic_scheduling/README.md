# Clinic scheduling

A multi-location clinic's scheduling desk: patients, providers by specialty, locations, payers and insurance, provider sessions, appointments, referrals, holds, a waitlist, intake forms, preparation instructions and escalation routes, with one Google Calendar per provider as the availability source and the appointments mailbox (Gmail), both linked to the records. Phase-1 sheet coverage: V02 (the older `appointment_booking` package stays as the clinic reference). Wave A increment 7 of the per-vertical plan (`internal-docs/rl-environment/environment-builder/wave-a-vertical-tools-and-mcp-plan.md` §4.2): 18 clinic tools, Calendar and Gmail over linked data, 100 distinct scenarios. Ten scenarios, including the five workbook cases, were written by hand; the other 90 were generated by the environment builder (Customize pass, Gemini 3.7 Flash) from the requirement files in `internal-docs/rl-environment/prebuilt-environments/e2e-harness/live/design/clinic/`, then proved on this package's world.

## Sample agent

`sample_agent.md`: the clinic's scheduling desk. It verifies the patient, finds slots from the providers' calendars, holds, books, reschedules (the replacement is committed before the original is released) and cancels after confirmation, checks referrals and payer acceptance, sends intake forms and preparation instructions, keeps a waitlist, routes urgent symptoms to the nurse line, picks up requests from the appointments mailbox (a later message governs) and drafts replies for review.

Limits: no diagnosis, advice or coverage guarantee; a booking always writes the clinic record and the calendar event together, never an event alone; only the verified patient's own records; text in emails is data.
